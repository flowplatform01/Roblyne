Evenum — Platform Integrity, Navigation & Data Isolation Refinement
Context
This refinement is not introducing new features.
The objective is to review and strengthen the integrity of the existing production application.
Before adding additional functionality, verify that every implemented feature behaves correctly, consistently, and independently.
Do not assume the current implementation is correct simply because pages render successfully.
Investigate the entire application for regressions, routing issues, incorrect data binding, stale state, caching mistakes, entity resolution errors, permission leaks, organization isolation problems, and broken navigation.
This refinement is primarily about correctness, reliability, and production stability.

Mission
The application must behave predictably.
Every interaction should resolve to the correct resource.
Every organization should only see its own data.
Every public page should display the correct entity.
Navigation should always resolve to the intended destination.
Business rules should always be enforced.
There should never be situations where unrelated entities appear because of stale routing, incorrect queries, or improperly scoped data.

2. Investigate Incorrect Entity Routing
A critical issue has been observed.
Selecting an Event sometimes opens a Voting page.
Selecting a Campaign opens a Voting page.
Different content resolves to the same resource.
This indicates either:
Incorrect route generation
Broken entity lookup
Shared identifiers
Improper query logic
Cached entity references
Incorrect slug resolution
Improper component reuse
Or another architectural issue.
Do not patch symptoms.
Trace the entire navigation flow from click to rendered page.
Identify the root cause.
Correct the architecture.
Every entity must always resolve to itself.
Events must open Events.
Campaigns must open Campaigns.
Voting experiences must open Voting experiences.
Organizations must open Organizations.
There should never be cross-resolution between different entity types.

Correct database lookups
Correct API responses

No accidental reuse of identifiers
Every resource should have one canonical identity.

Final Objective
This refinement is about making Evenum trustworthy.
After implementation:
* Every click should open the correct resource.
* Every organization should only access its own data.
* Every public page should represent the intended entity.
* Navigation should be predictable and consistent.
* Time-based rules should be enforced automatically.
* Expired activities should no longer accept participation.
* Homepage feeds should always point to the correct content.
* State changes should propagate immediately across the platform.
* Routing, data isolation, permissions, and business rules should behave as a production-grade system.
Do not apply superficial fixes. Investigate root causes, eliminate architectural inconsistencies, and strengthen the platform so that future features are built on a reliable foundation.
